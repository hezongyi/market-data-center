# v0.3.3 — provider gap and release validation hardening

Patch release following the PR #72 audit and PR #73 merge. The API and dataset
contracts remain compatible with v0.3.2.

## Fixes

- Derived maintenance downgrades only explicit `ProviderGapError`; structural
  `ValueError` failures remain failed.
- Provider gap failures are retryable while structural validation failures stay
  non-retryable.
- Fixed capacity measurements reject ratios outside `[0, 1]`.
- Documentation consistency checks use the configured deployment manifest and
  handle missing documentation files safely.
- Web UI lock metadata matches the 0.3.3 package version.

## Verification

The release branch must pass the protected-main `verify` check. Production
activation must retain stage and activation receipts and verify readiness,
metrics, smoke, and API/worker deployment identity against the immutable tag.

## Rollback

Roll back to the previous verified immutable deployment using the deployment
module; do not modify canonical parts, manifests, terminal receipts, or the
ledger.
