# v0.3.1 — provider gap 分级与容量门禁确定性

Patch release；`/api/v1` 与既有 dataset 查询契约保持兼容。

## 修复

- **provider gap 不再被报成硬失败**：新增 `ProviderGapError`（`ValueError` 子类），在 provider 确认"该区间无数据"的路径上抛出；1m maintenance runner 将其记为 `degraded`，不再计入 target 失败，`result` 在仅存在 degraded 时保持 `pass`，因此计划任务不再每轮报 `result=failed`。cooldown 抑制的 gap 同样记为 `degraded`。
  - 诊断依据：生产连续 5 次 `3/8 failed`（BTCUSD/EURUSD/USDCAD）；真实 provider 复现显示这些窗口确实无数据（对照窗口正常返回 16 行）；456 条 gap_repair 记录中 1 分钟窗口 81 次全部失败。数据侧 `quality_status=pass`，未被伪造或丢失。
  - 边界：完整性错误（重复/乱序/缺失 OHLC/非预期 selector）仍抛普通 `ValueError` 并使 target 失败，不会被降级掩盖。
  - 派生路径同时接受 `ProviderGapError` 与历史 `ValueError`，既有 degraded 行为不回退。
  - `ProviderGapError` 是 `ValueError` 子类，既有的"ValueError 不可重试"规则继续生效，不产生重试风暴或 dead-letter 堆积。
- **容量门禁确定性**：`scripts/operations_acceptance.py` 不再依赖宿主文件系统占用（`warning_free_ratio=0.99` 要求底层文件系统被占用 >1%，空 tmpfs 上必然失败）。新增 `FixedCapacityPolicy` 作为测量接缝，演练对显式 snapshot 断言门禁语义。
- **测试**：`test_delivery_timeout_and_retries_are_bounded_by_total_budget` 改为断言语义界限（预算在至多两次尝试后终止重试循环），不再依赖墙钟时间。

## 运行时与依赖

## Protected-main evidence
