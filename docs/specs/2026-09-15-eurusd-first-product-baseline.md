# EURUSD 首个闭环：产品与 WebUI 基线

日期：2026-09-15
状态：approved
批准依据：维护者在本日讨论中明确“认可你以上的全部提议”，包括独立开发、shadcn-admin、阶段预览与风险分级评审。批准设计与实施方向不等于代码、产品验收或生产发布已完成。

## 1. 唯一当前交付目标

用户在 WebUI 自行创建 Dukascopy EURUSD 维护任务，拉取 BID 1m、派生 5m、持续调度、管理异常，通过界面与 HTTP 查询相同结果；再自行创建一个已支持的 GBPUSD 任务，证明可复用。

本规范决定当前范围和产品验收；[预览规范](2026-09-15-isolated-preview-environment.md)决定预览隔离与交付；[开发指南](../development-guide.md)决定协作门禁；[实施路线图](../plans/2026-09-15-eurusd-first-implementation.md)只规定工作顺序。研究文档和上游示例不是规范。旧规范的范围冲突按第 5 节处理；已发布的数据身份、API 和不可变记录契约继续有效。

## 2. 范围与语义

- 首次可用切片：EURUSD / Dukascopy / BID / 原始 1m / 派生 5m。首轮真实源验收选最近一个已可用的完整交易日，记录实际 UTC 半开窗口。
- 用户可配置历史起点和维护频率；长历史以有界窗口后台推进。全历史完成不阻塞首次可用验收，不以最近有 bar 冒充全范围覆盖。
- 其它已注册派生周期在 5m 闭环通过后按需增加，不默认启用全部周期。GBPUSD 使用相同 1m→5m 流程验收，互不影响。
- 新增任务仅承诺已注册 provider/instrument/recipe。任意新 provider、品种元数据 CRUD、ASK/MID、economic/PIT、周/月线和全量迁移不在本轮。
- 任务定义、一次 execution、其内部 step/run 与已发布数据是不同对象。排队不等于完成，计划 enabled 不等于 scheduler 有效派发，运行成功不等于数据没有缺口。
- 沿用当前暂停与在途收口语义，在 UI 说明；删除计划只删除定义/释放所有权，保留数据、历史和审计。未获得的源数据不得补造。
- 区分休市、源延迟、真实缺口、网络错误、结构错误；缺口有具体窗口和复查时间，不能无限短重试或堵塞其它完整桶/品种。
- 当前 180 分钟可用性缓冲/缺口冷却是项目策略，不是 Dukascopy 官方延迟承诺。UI 展示最新 bar、策略目标、最近运行和下一次运行，不虚构“实时”或 ETA。

## 3. WebUI 技术与视觉约束

采用 `satnaing/shadcn-admin` 固定版本的成套设计，来源记录见[本地参考](../references/shadcn-admin.md)。在现有 `webui/` 内渐进替换，保持一个正式前端工程与构建产物。

必须实际引入所选 shadcn-admin 组件所需的 Tailwind、Radix/shadcn 基础与动画依赖，并保留 shell、sidebar、theme、表格工具栏、表单、sheet/dialog 的设计一致性。不能把手写同名组件或自制全局 CSS 称为已经采用 shadcn。上游 package.json 不整体照搬；按组件需求锁定兼容依赖。

`webui/AGENTS.md` 是所有前端改动必须遵循的实施入口。局部数据图表、业务排版和必要组件修正允许 CSS；禁止重造已有基础控件、增加全局覆盖去模仿模板或为每个页面另建主题。若模板存在明确限制，记录原因与最小替代，再在预览中验收；改变整个设计方向须先修改本规范。

首批导航围绕数据任务、数据查看、运行与问题、设置；任务详情整合原始/派生数据、运行、缺口与调度。其它既有功能暂留兼容入口，高级运维不占据主操作路径。

默认中文，保留英文和时间显示约定。表单字段错误、loading/empty/error/pending、写入确认与失败恢复属于交付内容。动画沿用模板，尊重 reduced-motion；桌面/移动端、键盘焦点可操作。后台刷新不丢草稿、筛选和详情。

复用现有 typed API client/services；保留 envelope、request ID、cursor、snapshot、recipe、expected_version 和幂等含义。任务详情具有可直达 URL，刷新/后退正确；新路由需配套 SPA fallback，不吞 API/静态资源错误。TanStack Query/Router/表单依赖按实际切片引入。

复用当前真实 `/api/v1/auth/*` 和 HttpOnly cookie 会话；模板默认 mock 登录不进入业务。初始化、登录、退出、改密需可操作；不显示没有后端的注册/忘密/OTP/Clerk 登录。只读访问策略不因更换页面而默默改变，生产 secure cookie 不为预览放宽。

## 4. 验收标准

| 编号 | 通过条件 | 证据 |
| --- | --- | --- |
| E01 | 独立预览可访问、身份和数据模式明确，API/worker/scheduler 全部运行且隔离 | 预览规范 PV01–PV08 |
| E02 | shadcn-admin 实际依赖与复制来源可核对；用户确认任务列表、创建/详情的视觉与操作 | 来源清单、构建、桌面/移动端预览和用户反馈记录 |
| E03 | provider/品种/周期选项来自 capabilities API；用户预览并创建 EURUSD 任务，错误定位字段，冲突与重复提交有明确结果 | UI→真实 API→持久化读回；不使用模板演示选项冒充能力 |
| E04 | 手动运行发布 raw，再从固定 raw 输入派生 5m；UI 与 HTTP 读回一致 | task/execution/run、manifest/lineage 与查询样本 |
| E05 | 真实 scheduler 到期后连续两轮自动执行，下一次调度可解释 | 两轮时间链、结果、数据读回；无新增需有合理说明，至少一轮实际发布 |
| E06 | 编辑任务范围/调度有版本冲突提示；暂停/继续、进程重启、失败重试保持进度和幂等，操作不丢草稿 | 编辑后读回与下一轮采用新定义；隔离恢复验收，非只验证 current_execution 出现 |
| E07 | 缺口只影响相应桶，冷却后可复查；休市/延迟/结构错误不同处理 | 已知样本与独立预期、可注入时钟，完整 worker 链路 |
| E08 | 用户自行创建 GBPUSD，独立管理和查询；冲突拒绝、归档/删除保留数据历史 | 第二任务用户旅程 |
| E09 | capabilities、原始/派生/coverage、任务增查改/动作和运行详情有可复制 HTTP 例子，保留现有读契约 | API 验证与用户指南 |
| E10 | 用户完整旅程验收后，候选版本通过完整 gate；实际发布按既有授权核验单 writer、身份、恢复与自动更新 | 分别记录产品接受、tag 和生产验收，不能互相替代 |

正确性分三层：独立预期小样本（OHLCV、UTC/session/DST、gap、幂等）；隔离浏览器+API+scheduler+worker 全链路；有界真实 Dukascopy 沙箱/发布 canary。模拟与真实证据明确分开。时钟可注入的测试不真实等待数小时，真实自动运行观察按源可用性安排。

E05 分别保留受控源确定性检查和真实 Dukascopy 沙箱的两轮自动运行证据。真实验收至少一轮发布 raw 与对应完整 5m 桶，并由 HTTP/UI 读回；两次手工运行、只有 heartbeat 或只创建 execution 均不满足。若交易时段/源可用性暂不允许发布，标记待验证并保留可操作预览，不把等待变成旧仓库对照或阻塞其它独立工作。

不以 macro-market-lab 输出为真值，不要求本轮跨仓库 parity。保留内部数据质量/lineage/聚合检查，不能按 parity 名称全部删除测试。

## 5. 旧工作暂停与规范接续

自本决策起，先前计划中尚未完成、又不支撑 E01–E10 的开发默认暂停排期。保留旧分支、代码、证据与未完成项，不取消已有数据，不自动停生产服务/定时器，也不撤销维护系统可用性所必需的操作。

| 旧工作 | 当前处理 |
| --- | --- |
| provider migration、economic/PIT consumer、crypto 接管、其它 provider 扩面 | 暂停，移出当前完成条件 |
| 旧调度主规范的持久化、所有权、幂等、暂停/恢复、固定输入契约 | 保留，复用现有实现；仅闭环发现的缺口进入本轮 |
| 接管补充 TA01/TA02 缺口分类/冷却 | 保留正确性要求，由 E07 验证；已完成修复不重做 |
| TA03/TA05 自动续轮/FX raw | 由 E04–E06 的 EURUSD 闭环承担 |
| TA04 legacy 连续 ≥4h 影子对照 | 本轮不适用，替换为独立链路与真实源自动两轮；原历史证据仍不算旧验收通过 |

| 紧急数据正确性、凭证保护、当前服务故障、必要备份恢复 | 继续必要维护，不借此恢复全部旧路线图 |
